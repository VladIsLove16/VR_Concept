# Симулятор обслуживания конвейерной линии

Полный MVP на Unity 2022.3.62f3 и URP 14.0.12. Пять сценариев используют одну рабочую сцену: знакомство, замены датчика и толкателя с подсказками, затем обе замены без пошагового сопровождения. XR Interaction Toolkit 2.5.4 и Input System 1.7.0 обеспечивают взаимодействия; официальный XR Device Simulator позволяет проходить их клавиатурой и мышью.

## Запуск

1. Откройте проект в Unity 2022.3.62f3.
2. Откройте `Assets/ConveyorTrainer/Generated/Scenes/ConveyorTraining.unity` и нажмите Play.
3. Для клавиатуры выберите **Conveyor Trainer → Input mode → Keyboard simulator**, затем дайте фокус окну Game. Для шлема выберите **PC VR**. Подсказки управления находятся также в самой сцене.
4. Выберите правую руку клавишей Y или левую клавишей T. ЛКМ выполняет действие по лучу, G удерживает предмет. Для телепортации нажмите и отпустите ЛКМ, направив луч на свободный пол.

| Команда симулятора | Управление |
|---|---|
| Выбор левой / правой руки | T / Y |
| Временное управление левой / правой рукой | Left Shift / Space |
| Управление головой | Удерживать ПКМ |
| Перемещение выбранного устройства | WASD, Q / E |
| Поворот или перемещение мышью | R переключает режим; Ctrl временно включает поворот |
| Удержание предмета | G — Grip |
| Рабочее действие / интерфейс | ЛКМ — Trigger |
| Телепортация | ЛКМ по свободному полу, затем отпустить |
| Смена режима движения WASD | 1 — ось стика, 3 — положение устройства |

У симулятора состояние захвата сохраняется при переключении управляемой руки. Можно удерживать ключ одной рукой, выбрать вторую и перенести датчик. Если G был нажат при переключении, вернитесь к этой руке и отпустите захват. Для работы инструментом поднесите его рабочую часть к гайке или болту и нажмите ЛКМ. У занятой руки рабочий луч отключён; кнопки, интерфейс и телепортация доступны свободной руке. Для размещения переместите предмет к выделенному месту и отпустите G. При отпускании вне допустимого места предмет возвращается в предыдущее законное положение, попытка учитывается как ошибка.

В режиме PC VR предмет берётся рядом с рукой или по лучу при удержании Grip. Grip можно нажать до касания; ближний захват имеет приоритет перед лучом. Луч выбирает ближайший предмет. При отказе отпустите Grip перед следующей попыткой: одно удержание считается одной попыткой для данного предмета. Для действия инструментом поднесите его рабочую часть к крепежу и нажмите Trigger. Свободной рукой используйте луч и Trigger для кнопок и World Space UI. Для телепортации наведите луч на свободный пол, нажмите и отпустите Trigger. Правый стик или тачпад вбок поворачивает персонажа на 30°. Те же способы подбора доступны в симуляторе.

## Где редактировать

- `Assets/ConveyorTrainer/Generated/Scenes/ConveyorTraining.unity` — размещение мастерской, экземпляры оборудования, ссылки между объектами.
- `Assets/ConveyorTrainer/Generated/Prefabs` — оборудование, инструмент, шайба, места установки, интерфейс, XR-персонаж и переиспользуемая геометрия.
- `Assets/ConveyorTrainer/Generated/Scenarios` — пять описаний сценариев: начальная неисправность, инструкции, условия и цели подсветки.
- `Assets/ConveyorTrainer/Generated/Input` — редактируемые XR Input Actions и ссылки на действия.

Меню **Conveyor Trainer → Create MVP Scene (once)** используется для первоначальной сборки. Если сцена уже существует, команда открывает её и ничего не пересоздаёт. Последующие изменения выполняются в сцене и префабах. Команда **Apply PC VR controls to existing project** адресно обновляет XRPlayer, инструменты и привязки ввода, сохраняя расстановку оборудования и данные сценариев. Повторный запуск не создаёт копии компонентов.

Интерфейс сохранён в префабах World Space Canvas. Во время игры меняются тексты, доступность кнопок и подсветка. Иерархия интерфейса во время игры не создаётся. Позиции текстов и кнопок, размеры, цвета и шрифты редактируются в `TrainingPanel.prefab`, `Text.prefab`, `Button.prefab` и `WorldLabel.prefab`.

## Правила MVP

- Обслуживание выполняется при остановленной линии. Остановка удаляет шайбы и отменяет ожидающие команды толкателя.
- Кабель и трубки переключаются только у закреплённого оборудования.
- Закрытие подачи воздуха сохраняет остаточное давление. Стравливание возможно после закрытия подачи; трубки переключаются только без давления.
- Датчик снимается после отключения кабеля и освобождения обеих гаек. Толкатель — после отключения обеих трубок, освобождения болтов и удаления давления.
- Перед освобождением гаек отключается кабель; перед освобождением болтов изолируется пневматика и отсоединяются трубки. Перестановка этих зависимых операций отклоняется. Порядок двух одинаковых креплений свободный.
- Каждая рука удерживает один предмет. Ключ работает с гайками, монтажный инструмент — с болтами.
- Порядок независимых креплений и трубок свободный. Сценарий проверяет условия, а не номер последней команды.
- Исходный и запасной экземпляры различаются. Обратная установка сломанного экземпляра не засчитывает замену.
- В конце ремонта обязательно подтверждение сортировки: металлическая шайба попадает в ящик, неметаллическая — в конец линии.
- В экзамене нет пошаговых инструкций и подсветки задания, но причина отказа показывается сразу.
- Одна отдельная попытка запрещённого действия — одна ошибка. В конце показывается количество ошибок без оценки и порога сдачи.
- Перезапуск создаёт новую попытку и восстанавливает оборудование. Продолжения с середины сохранённой попытки нет.

В сцене два крепления на каждый узел и две трубки толкателя. Пневматика имеет дискретные состояния подачи и остаточного давления. Шайбы перемещаются физически; вращение ограничено для устойчивой модели плоских деталей на примитивах. Эти упрощения ограничивают объём MVP.

## Архитектура

`Domain` — чистый C# без UnityEngine. `MaintenanceModel` владеет состоянием и проверяет действия; его состояние нельзя произвольно менять из интерфейса. `ProcedureTracker` отслеживает выполненные действия и повторно проверяет условия сборки и сортировки. Обе системы покрываются быстрыми Edit Mode тестами.

`Runtime` — адаптеры XR, физическая линия, сценовый интерфейс и сохранение. `TrainingStation` соединяет модель, описание сценария, отображение и хранилище. `MaintenanceTarget` передаёт рабочее действие в модель. `ServiceItem` связывает XR-захват с состоянием предмета и применяет удерживаемый инструмент к ближайшему крепежу у его рабочей части. `HandInteractionRouter` отдаёт Trigger удерживаемому предмету и отключает луч этой руки, исключая одновременное действие инструментом и нажатие кнопки или телепортацию.

`Editor` — первоначальная сборка сцены и префабов. Он не нужен в собранном приложении. `ScenarioDefinition` — авторские данные ScriptableObject; состояние прохождения хранится отдельно, сами assets во время игры не изменяются.

## Результаты

Попытки сохраняются отдельными JSON-файлами в `Application.persistentDataPath/Attempts`. Для текущих Company Name / Product Name на Windows это обычно `%USERPROFILE%/AppData/LocalLow/DefaultCompany/VR_Concept/Attempts`.

Формат содержит версию, идентификатор попытки и сценария, начало UTC, длительность, статус `in_progress` / `completed` / `interrupted`, выполненные обязательные условия, количество ошибок и их записи. Ошибка содержит действие, цель, причину и время от начала попытки. Сохранение выполняется после действий, при завершении, прерывании и паузе. Перезапись файла использует временный файл с атомарной заменой.

## Проверка

Откройте **Window → General → Test Runner**. Edit Mode проверяет существенные правила, состояние процедур, JSON и контракт сцены. Play Mode проверяет физическую сортировку всех четырёх сценариев ремонта, захват и размещение, остановку, сброс, условия телепортации и путь клавиатура/мышь → XR Simulator → действие оборудования.

Политика тестов и критерии ручной приёмки описаны в `Docs/TEST_POLICY.md`. Результаты автоматических запусков находятся в `Logs/EditModeResults.xml` и `Logs/PlayModeResults.xml` и не включаются в Git.

Исторические результаты проверки MVP от 15 октября находятся в `Docs/VALIDATION.md`: 33 Edit Mode, 8 Play Mode, успешная Windows-сборка и проверка запуска с D3D11. Они не подтверждают последующие изменения управления. При обновлении PC VR автоматическое прохождение через симулированный ввод не выполняется. Критерии проверки на оборудовании приведены в `Docs/PC_VR_HANDOFF.md`.

## Реальный шлем

Целевая платформа — Windows PC VR с подключённым шлемом. Выберите **Conveyor Trainer → Input mode → PC VR** и запустите OpenXR runtime оборудования: Meta Quest Link для Quest либо SteamVR с соответствующим подключением для PICO/VIVE/Index. Команда включает OpenXR, отключает симулятор и дальний подбор, переключает отсчёт высоты на пол. Настроены профили Oculus Touch, HTC Vive, Valve Index, VIVE Focus 3 и PICO 4. Дополнительные профили используют стандартные расширения OpenXR; runtime выбирает поддерживаемые профили. Наличие профиля не является подтверждением работы на физическом устройстве. Подробности и известные ограничения — `Docs/PC_VR_HANDOFF.md`.

Для возврата к клавиатуре выберите **Conveyor Trainer → Input mode → Keyboard simulator**. Эта команда отключает автоматическую инициализацию OpenXR и включает симулятор, высоту камеры 1,65 м и дальний подбор. Переключать режим следует перед Play.

## Сборка

Рабочая сцена добавлена в Build Settings. Перед **File → Build Settings → Windows → Build** выберите режим **PC VR**. Метод редактора `ConveyorTrainer.Editor.MvpBuilder.BuildWindowsPlayer` выбирает PC VR и создаёт Development Build в `Builds/ConveyorTrainer`. В этой сборке симулятор отключён, используется D3D11.
