# PC VR — запуск и приёмка

Цель: Windows 10/11 x64 с подключённым 6DoF-шлемом и двумя контроллерами. Автономная сборка для шлема не входит в текущую задачу.

## Оборудование

Рекомендованный пример конфигурации, полученный от руководителя: Intel Core i5-12400 / Ryzen 5 5600, 16 ГБ ОЗУ, RTX 3060 / RTX 4060 с минимум 8 ГБ VRAM, SSD со свободными 15 ГБ. Требования к портам зависят от подключения. Целевая частота — 72–90 Гц. Минимальная поддерживаемая конфигурация пока не установлена измерениями.

Целевые семейства: Quest 3, PICO 4, HTC Vive, VIVE Focus 3; реже Valve Index. В проекте включены профили Touch, Vive и Index, а также минимальные стандартные OpenXR-профили Focus 3 и PICO 4 для используемых действий. Дополнительные профили не требуют SDK производителя. Если PC runtime не предоставляет соответствующее расширение, работа зависит от наличия совместимого профиля в этом runtime; автоматическая совместимость не подтверждена. Фактическую раскладку нужно проверить при первом подключении.

Quest подключается через Meta Quest Link либо совместимый PC runtime. Для PICO 4 требуется PC-подключение, например PICO Connect со SteamVR; для Focus 3 — VIVE Business Streaming и поддерживаемый PC runtime. Приложение запускается на ПК. Системный OpenXR runtime выбирается в ПО оборудования, проект не меняет его автоматически.

## Запуск готовой сборки — для руководителя

1. Получить `Builds/ConveyorTrainer-PCVR-2026-10-23.zip` и полностью распаковать его. Внутри папки есть `README_RU.txt` с короткой инструкцией. Рядом с EXE должны оставаться папка данных и остальные файлы сборки.
2. Подключить шлем к ПК, запустить его PC runtime и убедиться, что он назначен активным OpenXR runtime.
3. Запустить `ConveyorTrainer.exe` из распакованной папки.

Unity и исходный проект для этого варианта не нужны. Переданная сборка уже подготовлена для PC VR: симулятор отключён, OpenXR включён. Команды редактора не меняют ранее собранный EXE.

## Запуск исходного проекта в Unity

1. Открыть проект в Unity 2022.3.62f3 и сцену `Assets/ConveyorTrainer/Generated/Scenes/ConveyorTraining.unity`.
2. Перед Play выбрать **Conveyor Trainer → Input mode → PC VR**. Для клавиатуры предусмотрен пункт **Keyboard simulator**.
3. Подключить шлем, запустить его PC runtime и убедиться, что он назначен активным OpenXR runtime.
4. Нажать Play в Unity.

Первоначальная команда **Apply PC VR controls to existing project** уже выполнена и сохранена в проекте. Повторять её перед запуском не требуется.

## Повторная сборка — для разработчика

Если нужно собрать новую версию вручную: выбрать **Conveyor Trainer → Input mode → PC VR**, затем **File → Build Settings**, платформу Windows x64 и **Build**. Передавать всю полученную папку сборки. Метод `MvpBuilder.BuildWindowsPlayer` выбирает PC VR автоматически.

Текущая сборка в `Builds/ConveyorTrainer` уже создана этим методом; перед её передачей выполнять команду в Unity или пересобирать проект не требуется.

## Управление

| Действие | Контроллер |
|---|---|
| Подобрать предмет | Поднести руку к предмету и удерживать Grip |
| Поставить предмет | Перенести в выделенную область и отпустить Grip |
| Работа инструментом | Поднести его рабочую часть к гайке/болту и нажать Trigger |
| Кнопки оборудования и UI | Луч свободной руки + Trigger |
| Телепортация | Луч на свободный пол, нажать и отпустить Trigger |
| Поворот на 30° | Правый стик/тачпад вбок |

У каждой руки независимый захват. При удержании предмета луч этой руки отключается; другая рука остаётся доступной. Остановка линии требует одной свободной руки. Вращение кистью при затяжке не моделируется. Инструмент и предметы остаются примитивами.

В симуляторе: T/Y выбирают руку, G отвечает за Grip, ЛКМ — за Trigger. Удержание сохраняется при переключении рук. Подбор лучом оставлен для удобства клавиатурной проверки, а работу инструментом нужно выполнять рядом с крепежом. Режим меняется до Play.

## Короткая проверка на оборудовании

Проверка выполняется человеком. Автоматические сценарии Play Mode с имитацией контроллеров не являются критерием приёмки этого изменения.

- Голова и обе руки отслеживаются; пол и высота соответствуют пользователю.
- Каждая рука подбирает предмет рядом с ним и отпускает его в допустимое место.
- Инструмент действует на ближайший крепёж у рабочей части; неподходящий инструмент вызывает существующий отказ.
- Trigger с удерживаемым инструментом не вызывает одновременно нажатие кнопки или телепортацию.
- Свободная рука останавливает линию, нажимает кнопки UI и выполняет телепортацию.
- Правый стик/тачпад поворачивает персонажа; неподвижный контроллер самопроизвольно его не вращает.
- Ремонт датчика и толкателя можно завершить обычным управлением, результат сохраняется в JSON.

При проверке записать модель шлема, способ подключения, OpenXR runtime, конфигурацию ПК и версию сборки. Если обнаружен дефект, записать действие и фактический результат.
