# Политика тестирования MVP

Тесты выбираются по рискам и критериям приёмки. Целевой процент покрытия не используется.

Проверяем правила обслуживания, критические переходы состояний, прохождение сценариев, регистрацию ошибок, сброс уровня и основные интеграции Unity/XR. Каждая проверка должна иметь конкретное требование либо вероятную регрессию.

Edit Mode используется для правил и данных. Play Mode — для физики, жизненного цикла, взаимодействий и интеграции сцены. Проверяется наблюдаемое поведение; тривиальные свойства, присваивания, детали реализации и стандартное поведение Unity отдельно не тестируются. Одно правило не дублируется на обоих уровнях без отдельной причины.

Критическое правило получает успешный случай и существенные причины отказа. Полный перебор комбинаций состояний не требуется. Однотипные случаи параметризуются; число проверок считается с учётом параметров. Дополнительные тесты обосновываются новым риском, изменением требования либо обнаруженной ошибкой.

## Связь с требованиями

| Группа | Риск, который проверяется |
|---|---|
| Подача и давление | Закрытый кран ошибочно считается отсутствием давления; соединения снимаются под давлением |
| Снятие и установка | Неподходящий инструмент, незавершённый крепёж, занятые руки, замена неправильной деталью |
| Сценарии | Допустимый порядок ошибочно штрафуется; начальное состояние засчитывается как выполненная процедура; устаревшая проверка сортировки завершает ремонт |
| Физическая линия | Команды дублируются, срабатывают после остановки или шайбы попадают не в тот выход |
| XR | Захват не совпадает с состоянием модели; симулированный ввод не доходит до рабочих действий и кнопок сценового интерфейса; удержание запрещённого захвата многократно добавляет ошибку |
| Сохранение и сцена | Результат теряется при обновлении JSON; отсутствуют ссылки или данные пяти сценариев |

Один Play Mode тест проходит все четыре сценария замены с реальной физической сортировкой. Проверки правил внутри этих процедур выполняются отдельно в Edit Mode. Число тестов не равно числу проверяемых сценариев.

## Ручная приёмка

1. Пройти все пять сценариев через клавиатуру и мышь, без прямого вызова методов из тестов.
2. Проверить переключение рук при удержании инструмента, чтение подсказок, отпускание вне места установки и возврат предмета.
3. На экзамене совершить запрещённое действие, увидеть причину сразу, завершить ремонт и сверить итоговое количество с JSON.
4. Отредактировать префаб панели и проверить сохранение правки; команда первоначальной сборки не должна перезаписывать сцену.
5. Запустить Windows-сборку и проверить кириллицу, размеры интерфейса и запись результата.
6. На реальном шлеме отдельно проверить масштаб, удобство захвата, телепортацию и читаемость World Space UI.
