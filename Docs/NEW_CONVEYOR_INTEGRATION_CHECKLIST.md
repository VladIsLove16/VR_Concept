# Адаптация MVP к новой модели конвейера

## Согласованная конфигурация на 11 ноября 2026 года

Для толкателя используется одна операция с крепежом на `PusherBolt_01`. Две гайки датчика и два пневматических подключения остаются отдельными. При отсоединении скрывается меш соответствующего кабеля или шланга. Разъём остаётся доступным для повторного подключения.

Миграцию существующей сцены выполняет **Conveyor Trainer → Integrate Conveyor Model (once)**. Рабочая сцена использует `Conveyor.prefab` для неподвижной части, а установленные и запасные модули используют `ConveyorSensor.prefab` и `ConveyorPusher.prefab`. Точки установки, привязки и физические зоны сохранены в сцене.

## Исходный аудит модели

Проверено 9 ноября 2026 года: `Assets/ConveyorTrainer/Generated/Prefabs/Conveyor.prefab`, сохранённая `ConveyorTraining.unity`, компоненты взаимодействия, симуляции и правила обслуживания. Это список изменений для согласования; сцена, модель и код при составлении списка не изменялись. Новые расстояния и ход механизма не измерялись в Unity.

## Что уже названо и что необходимо уточнить

Найдены `StartButton`, `StopButton`, `SensorBody`, `SensorMount`, `SensorNut_01`, `SensorNut_02`, `SensorIndicator`, `PusherAssembly`, `PusherMovingPart`, `PusherRod`, `PusherBody`, `PusherMount`, `PusherBolt_01`, `Belt`, `MetalChute`, `MetalBin`.

- У `PusherAssembly` и `PusherBody` есть пробелы в конце имени. Удалить их для однозначной разметки.
- Нет именованных `SensorConnector`, `PusherConnector_01`, `PusherConnector_02`, `AirShutoffValve`, `VentValve`.
- Из четырёх точек крепления именована только `PusherBolt_01`. Выделить и назвать остальные три. Если это лапки, отдельно определить крепёж, с которым работает инструмент; не подменять болт всей лапкой только из-за её расположения.
- Сейчас `PusherMovingPart` содержит `PusherRod` и `PusherBody`. Если второй объект — круглая толкающая головка, назвать его `PusherHead`. Настоящий корпус не должен перемещаться вместе со штоком при рабочем ходе.
- Сейчас `PusherMount` находится внутри `PusherAssembly`. Если это неподвижная подставка, вынести её из съёмной сборки. Если этим именем назван корпус механизма, переименовать его в `PusherBody` и оставить внутри сборки, но вне движущейся группы.
- `SensorIndicator` сейчас находится вне `SensorBody`. Проверить, что назначен нужный светящийся участок. Для индикатора на пульте такое расположение допустимо; встроенный в датчик индикатор должен следовать за съёмным корпусом.
- Нормализовать управляющие корни: сейчас Scale у `SensorBody` — 100, у `PusherAssembly` — около 151.36, у ряда мешей — около 178, у вложенного `konveer` — 0.5. Сами значения не доказывают неправильный размер. Для физики и установки нужны корни с понятными осями, pivot и единичным масштабом; геометрию можно оставить дочерним Visual, сохранив её мировой размер. Простая замена Scale на 1 изменит вид модели.

Целевая структура толкателя:

```text
Conveyor
├── PusherMount                 неподвижная подставка
└── PusherAssembly              снимаемая сборка
    ├── PusherBody              корпус, неподвижный относительно сборки
    └── PusherMovingPart        перемещаемая группа
        ├── PusherRod
        └── PusherHead
```

Префаб использует меши из `Assets/Models/konveer.fbx`. Файл `konveer 1.fbx` также присутствует в проекте, но меши проверенного префаба ссылаются на исходный `konveer.fbx`; если второй файл содержит необходимые исправления, их использование нужно согласовать отдельно.

## Что заменить и куда перенести

| Физическая поверхность Belt | Создать простые коллайдеры по новой рабочей поверхности, бортам, направляющим и спуску. Проверить высоту шайб и проход к боковому отводу. |
| Washer Spawn | Перенести к входному концу новой ленты, над рабочей поверхностью с учётом размера шайбы. Установить направление вдоль движения. |
| Sensor Detection | Перенести к чувствительной части SensorBody. Подогнать ширину/высоту триггера под путь шайб, чтобы он не ловил шайбы на столе, в ящике или на соседнем участке. |
| Pusher Striker / PusherActuator | Перенести работу привода на PusherMovingPart. Коллайдер толчка должен соответствовать PusherHead. Определить начальную и конечную позиции относительно сборки. |
| Metal Collector | Разместить внутри MetalBin под новым спуском; подогнать объём по реальному месту попадания шайб. |
| End Collector | Перенести за выходной конец новой ленты для неметаллических шайб. Проверить, что он не пересекает боковой маршрут металла. |
| Sensor Mount и его Anchor | Поставить в место крепления датчика, согласовать ориентацию и точку установки с pivot SensorBody. Видимый кронштейн и служебная точка установки — разные роли. |
| Pusher Mount и его Anchor | Поставить на неподвижную подставку; согласовать позу установки PusherAssembly. Подставка остаётся при снятии механизма. |
| Старый и запасной датчики | Использовать визуал SensorBody с отдельными XR-корнями, коллайдерами, Rigidbody и точками захвата. Проверить размещение обоих экземпляров. |
| Старый и запасной толкатели | Использовать съёмную PusherAssembly. При переносе не оставлять шток/головку в старой мировой позиции. |
| Подсветка и отображение состояния деталей | У ServiceItem сейчас одна ссылка visual на Renderer. В новой модели съёмные узлы состоят из нескольких мешей: определить набор подсвечиваемых Renderer и сохранить исходные материалы остальных частей. |
| sensor.cable, sensor.nut.0/1 | Перенести взаимодействия на разъём и две реальные гайки. Подогнать области попадания инструмента и подсветку. |
| pusher.tube.0/1, pusher.bolt.* | Перенести на нужные два разъёма и четыре точки крепления. Не назначать произвольные синие трубки без определения их назначения. |
| power | Привязать две кнопки пульта к отдельным действиям пуска и останова. Обе кнопки нельзя просто назначить на текущее переключение состояния. |
| air, vent | Привязать к реальному крану перекрытия и органу стравливания после их разметки. |
| Sensor Lamp | Назначить Renderer для SensorIndicator. Если индикатор встроен в заменяемый датчик, обновлять ссылку на установленный экземпляр. |
| Стол и Bench Slot Wrench/Driver/SensorOriginal/SensorSpare/PusherOriginal/PusherSpare | Проверить расположение стола относительно новой длины линии. Передвинуть шесть мест и подписи; увеличить расстояния между местами крупных деталей при необходимости. |
| Точки захвата и Work Tip инструментов | Подогнать под реальную геометрию. Радиус применения менять только после проверки попадания в отдельный крепёж, чтобы не задевать соседний. |
| Training Panel, Simulator Controls, три кнопки i и подписи | Перенести к доступным сторонам оборудования; исключить пересечения с новой рамой, шкафом и трубками. |
| Пол и телепортация | Расширить пол при необходимости. Добавить новые статические препятствия в проверку свободного места, сохранить доступ к пульту, столу, датчику и толкателю. |

В новом префабе есть Transform, MeshFilter и MeshRenderer, но нет Collider, Rigidbody и компонентов механик. Физические слои тоже нужно назначить: статическое оборудование/органы управления — слой 8, коллайдеры переносимых предметов — слой 10. Для интерактивных целей используются XR-маски 1 (действия) и 2 (захват); статической геометрии XR-компоненты не нужны. Один корневой Layer не распространяется автоматически на существующих детей.

## Какие параметры и код требуют адаптации

| Текущее значение или ограничение | Что изменить |
|---|---|
| ConveyorLine двигает шайбы по мировому +X | Задать направление относительно новой ленты. Перенос/поворот визуального префаба сам по себе направление кода не изменяет. |
| beltXLimits = −2.5…2.5; beltHalfWidth = 0.42; высота захвата движения = 0.65…1.05 | Заменить старые мировые границы областью новой ленты. Учесть её фактическую высоту и ориентацию. Одного переноса Washer Spawn недостаточно. |
| sensorDelay = 1.69 с; beltSpeed = 0.65 м/с | Пересчитать время от датчика до места толчка. Начальная оценка — продольное расстояние / скорость; затем проверить с учётом времени выдвижения и реального прохода шайбы. |
| PusherActuator.travel = 1.05 м; направление — мировой +Z; speed = 3.2 м/с | Согласовать ось с новой головкой и задать начало/конец хода. Ход должен вывести шайбу за перегородку в отвод, но сохранять соединение штока с корпусом. Увеличение хода пока не подтверждено измерением. |
| Исходная позиция толкателя сохраняется в Awake как мировая координата | Хранить положение покоя относительно съёмной сборки, чтобы при снятии и установке подвижная часть не возвращалась в старую мировую точку. |
| Крепёж толкателя: массив из двух состояний, индексы 0…1 | Перевести правила, цели взаимодействия, проверку завершения, сброс, подсказки и связанные проверки на четыре согласованные точки крепления. Датчик и пневмоподключения остаются по два. |
| Operation.Power переключает Running | Разделить намерения Start и Stop; повторный Stop не должен запускать линию. Сохранить проверки готовности оборудования перед пуском. |
| ItemSocket.captureRadius = 0.35 м | Проверить отдельно для новых поз установки и мест на столе. Радиус должен прощать неточность руки, но не смешивать соседние места. |
| ServiceItem.workRadius = 0.06 м | Проверить на реальном расстоянии между креплениями и размере рабочей части инструмента. Не увеличивать вслепую. |

Порядок работы: завершить разметку и структуру → зафиксировать размеры/оси → заменить геометрию и физику → расставить точки и зоны → настроить ход и задержку → проверить оба ремонта, сортировку и доступность в VR. Точные новые позиции, размеры триггеров и амплитуда определяются после измерения модели в финальном положении, а не по значениям Scale.
