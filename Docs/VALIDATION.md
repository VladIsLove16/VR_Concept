Edit Mode проверяет условия обслуживания, инструмент в конкретной руке, крепёж и соединения, давление, допустимый порядок независимых действий, размещение, сброс, актуальность проверки сортировки, JSON и ссылки сцены. Параметризованные варианты считаются отдельными проверками.

Play Mode проверяет:

1. Остановку с удалением шайб и отменой команд толкателя.
2. Распознавание металла, игнорирование пластика и отсутствие повторной команды от одной шайбы.
3. Завершение знакомства после изучения оборудования и доступность следующего сценария.
4. Все четыре сценария замены с физической сортировкой обоих материалов; проверка не подменяется ручной отметкой завершения.
5. Однократную регистрацию запрещённого действия и полный сброс работающей линии при перезапуске.
6. Захват и отпускание предмета через XR Interaction Manager с синхронизацией модели.
7. Свободное и занятое место для телепортации.
8. Синтетические состояния клавиатуры и мыши в игровом цикле → официальный XR Device Simulator → контроллер → действие оборудования; одна ошибка при удержании запрещённого захвата; переход на следующий сценарий через кнопку World Space UI.

Полный Play Mode прогон включает четыре физических процедуры внутри одной проверки. Поэтому восемь тестов не означают восемь отдельных пользовательских действий.

## Исправление регистрации профилей — 23 октября 2026 года

В `ThumbstickControllerProfile.RegisterDeviceLayout` явно передано имя layout в аргумент `name` метода `InputSystem.RegisterLayout`. В Input System 1.7.0 имя внутри JSON не используется при регистрации переданного отдельно matcher, что вызывало `ArgumentNullException: layoutName` для профилей PICO 4 и VIVE Focus 3.

Добавлены два параметризованных Edit Mode случая: регистрация профиля, выбор layout по описанию контроллера и повторная регистрация. Они выполнены в отдельном временном проекте Unity 2022.3.62f3 с копиями трёх исходных файлов профилей и теста, Input System 1.7.0 и OpenXR 1.11.0; основной редактор оставался открытым.

- До исправления: оба случая воспроизводят исходное исключение (`Logs/ControllerLayoutsBefore.xml`).
- После исправления: 2 из 2 проходят (`Logs/ControllerLayoutsAfter.xml`, `Logs/ControllerLayoutsIsolatedAfter.log`).

Полный набор тестов, запуск всей сцены и инициализация с физическим шлемом в этой проверке не выполнялись. Windows EXE не пересобран; для передачи исправления в готовую сборку требуется пересборка.

## Исправление захвата и обычная сборка — 29 октября 2026 года

Выполнено локальное воспроизведение взаимодействия в сохранённой сцене. На исходной конфигурации XRDirectInteractor с `StateChange` датчик обнаруживался рукой, но не брался, если Grip был нажат до входа в контакт. Нажатие после контакта, перенос и размещение работали. Подтверждение: `Logs/SensorGrabBefore-20261029.xml` (сбой `PreparedSensorCanBeTakenWhenGripWasPressedBeforeContact`). Это воспроизводимая локальная проблема; присланные журналы не позволяют доказать, что руководитель столкнулся именно с этим порядком ввода.

Изменено:

- Захват использует состояние удерживаемого Grip, поэтому нажатие до касания не теряется. Отказ запоминается для данного контроллера и предмета до отпускания Grip: удержание не порождает ошибку каждый кадр.
- В PC VR доступен и захват лучом. Штатный XRInteractionGroup отдаёт приоритет ближнему интерактору и не позволяет одной руке одновременно выбирать предмет обоими путями. Луч подбора проверяет слой переносимых предметов и выбирает ближайший; коллайдеры кнопок кабеля не мешают взять корпус датчика. Луч Trigger для оборудования и UI сохраняется.
- Правила остановки, отключения кабеля, освобождения крепежа и свободной руки сохранены. Оборудование и сценарии не пересоздавались. Обновлены существующий XRPlayer.prefab, сцена и инструкция управления.
- В тестах добавлены четыре адресные проверки; очистка входных действий перед выгрузкой тестовой сцены предотвращает assert Input System 1.7.0 при удалении устройств симулятора. Это изменение тестового жизненного цикла не включается в Player.
